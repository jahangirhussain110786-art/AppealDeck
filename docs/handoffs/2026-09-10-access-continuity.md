## Discovered during this pass

- **Critical (found by audit, fixed in `50dbd4c`):** the sign-in gate at the first document step never actually blocked progress — `case/page.tsx` rendered `SignInGate` as a static banner above the whole interview instead of the step card being replaced, and `InterviewFlow.tsx` had no `signedIn`-aware check on the file step at all. A signed-out visitor could complete the entire interview, including uploads.
- **Critical (found by audit, fixed in `50dbd4c`):** `VaultGate.tsx`'s `needs_init` and `device_set_passphrase` phases called their own internal `onDone` but never the external `onUnlocked` prop. `InterviewFlow` depends entirely on `onUnlocked` to leave its own vault-gate fallback render (it passes `{() => null}` as children). Result: after setting a passphrase to relock a device-mode vault, the interview area went blank instead of resuming — recoverable only by a manual reload. Fixed by having both phases call `onUnlocked` (the relock path passes `{ viaRelock: true }` so `InterviewFlow` can skip the resume dialog per S§2's "without a resume dialog" requirement).
- **High (found by audit, fixed in `50dbd4c`):** `case/page.tsx` rendered `<CasePreview kind={initialKind} />` only when `initialKind && signedIn` — meaning a signed-out visitor arriving from `/decode?...` via "Start your case — free" (the exact T0 audience) saw a generic "UNKNOWN" preview instead of their notice-specific evidence checklist.
- **High (found while writing the required e2e test, fixed in `50dbd4c`):** `?kind=` in the URL never actually started the interview for a fresh visitor — `InterviewFlow` set the `kind` state from the prop but nothing called `createCaseFile`/`handleStart`, so the component rendered nothing (`step` stayed null). Added an effect that auto-starts once, only when there is no existing case file to resume and no resume dialog pending.
- **High (found while writing the required e2e test, fixed in `50dbd4c`):** the signed-out auto-unlock path (`InterviewFlow`'s own vault-init effect, for a returning visitor whose device-mode vault is already initialized) unlocked the vault but never loaded the saved case file back into React state, so a page reload left the interview blank instead of resuming — the literal scenario S§11 item 1 requires. Fixed by loading and applying the existing case file in that branch too.
- **Critical, pre-existing in `src/core/interviewEngine.ts` (not part of A1–A4, found while writing the e2e walk, fixed in `50dbd4c`):** `nextStep` and `countCompletedSteps` treated `priorAppealCount === 0` as "the prior-appeals question is unanswered" — which is also the correct value for the most common real answer, "No, this is my first appeal." Selecting it looped the interview on the same step forever. The existing vitest fixtures never caught this because they hand-constructed `attemptCount: 1` to route around the check rather than driving it through `applyAnswer`. Added `priorAppealsAnswered: boolean` to `CaseFile` to track this explicitly, plus a regression test that drives the real `applyAnswer("no")` path.
- `SignInGate`'s "Create an account" link did not carry `?next=` (only "Sign in" did) — fixed alongside the above.
- Two of the prompt's own Accept-block greps do not literally match despite the underlying requirement being met, both harmless: (1) A1's `grep -n "user: { email" src/components/AppShell.tsx → 0 hits` — the nullable type is written inline as `{ email?: string | null } | null`, so the substring is unavoidably still present even though `user` is correctly nullable; (2) A3's `grep -n "extractable\|false, \[\"encrypt\"" src/core/vault/crypto.ts → ≥ 1 hit` — `generateDeviceKey` correctly passes `false` for `extractable`, but Prettier wraps the array onto the next line so the single-line pattern doesn't match.
- `compose/page.tsx` had no license/Pass check at all between task-2 (which removed the old no-pass card and its check together) and task-6 (which was always going to restore it via `ComposeGate`) — any signed-in user without a Pass could reach the full composer during that window. Confirmed closed by A6.
